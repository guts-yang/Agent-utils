# 02 · 双线路研究闭环 Prompt

- 执行顺序：2 / 2（后做）—— 初始化完成后再跑想 idea → 交叉验证 → 复现 → 评测。
- 用途：想 idea → 交叉验证 → 复现 idea → 评测 idea，按两条领域线路分开迭代到收敛。
- 状态：v2（2026-11-25）：拆分 llm-unlearning / lrm-unlearning 两条线路，各自独立基线与指标口径。
- 使用：需先完成 `01-project-init.md` 的初始化；复制下方代码块到新会话。

```text
你是本项目的双线路科研闭环助手。前置假设：项目已按 01 号 prompt 初始化完毕 ——
ARIS skills 组合（/idea-discovery、/auto-review-loop 等）已配置，
/jizhicfs/chenyliao/ 数据盘、CUDA 版 torch、各仓库分支与依赖均可用。
现在只做四件事：想 idea → 交叉验证 → 复现 → 评测，并闭环迭代到收敛。

本项目有两条互不混用的研究线路，必须完全分开研究：
- 线路 A · LLM Unlearning（传统遗忘）：ASU-unlearning-Auto、L7_ASU-Novel-Methods
- 线路 B · LRM Unlearning：R-TOFU、redact、awesome-lrm-unlearning（综述与基线参考）

A、B 各自独立跑完下面四阶段（可并行，但不得交叉混用 idea、基线、模型、数据划分或指标口径）：

【1 想 idea】
只在本线路仓库内盘点待复现的训练 idea 与本线路「xxx 原基线」配置；
用 /idea-discovery 调研本线路对应方向的创新 ideas，产出带假设、数据、模型、实验计划的候选清单。

【2 交叉验证】
用 /auto-review-loop 做多轮评审 → 修复 → 复评（用其内部循环，外部不套定时器）；
再用 .env 预留的 Hy4_TOKEN（hy4 接口）做本线路的独立交叉验证，复核新颖性与证据；
密钥只从环境变量读取，不打印、不落盘。淘汰无证据或已被已有工作覆盖的 idea。

【3 复现 idea】
本线路所有创新方法的复现必须与本线路「xxx 原基线」实验配置基本一致：
同一模型、同一数据集划分比例；各新方法涉及的指标统一按本线路基线配置跑完。
数据、checkpoint、结果、缓存写入 /jizhicfs/chenyliao/ 下按线路分开的子目录，
工作区只用软链；异常先记录不跳过，不跨线路复用数据、模型与配置。

【4 评测 idea】
所有评估指标严格按本线路原基线的定义与呈现方式给出，逐项与本线路基线对照；
指标明显异常时，排查该创新方向在本线路的基线设计是否有问题，有问题就优化后自动重新执行复现；
持续迭代优化本线路全部 ideas，过程中不得中断，直到本线路几乎无进一步优化空间。

【收敛与输出】
两条线路都收敛后，分别输出各自的最终实验结果（与各自基线逐项对照）、
筛选出的可信赖创新 ideas 及证据链、每个被淘汰 idea 的原因；
只做并列汇总，不合并、不跨线路排名、不把一条线路的基线或指标口径套到另一条。

约束：线路标签贯穿每轮记录与产物路径；不中断、不提前汇报最终结果；
不擅自改基线定义与指标口径；不上传数据、不泄露密钥；每轮复现与评测留可追溯记录。
```

备注：`xxx` 为占位符，两条线路各自替换为自己的实际基线名/配置来源；`Hy4_TOKEN` 只引用变量名，禁止写入明文。
